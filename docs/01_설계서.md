# AGV DCU 표 편집기 설계서

- 기준: 앱 저장소 `docs/09_표편집기_개발사양서.md`(2026-11-15 버전, 코어 v0.55.0). 아래에서 "사양 n절"은 그 문서의 절이다.
- 이 문서는 구조만 정한다. 문법(사양 4절), 검사 규칙(6절), 빌드·깃 명령(7·8절), 화면(9절)은 사양서가 원본이고 여기서 되풀이하지 않는다.
- 표시: **내 판단** = 사양서에 없어서 설계자가 정한 것. 사용자 확정이 아니다. 9절에 모았다.
- 이 저장소는 공개다. 2절의 경계를 지킨다.

## 1. 한 줄 요약

Windows 프로그램 하나. 사이트 C 표 파일을 조각 단위로 읽어 블록으로 보이고, 고친 조각만 다시 써서 같은 C 파일로 돌려준다. 검사 → 압축 태그 표 → C28x 빌드 → 커밋·회차까지 한 화면에서 한다.

| 항목 | 정한 것 |
|---|---|
| 저장소 | `AGV_DCU_TableEditor`(공개) |
| 실행 파일 | `TableEditor.exe`(화면), `tedit.exe`(명령줄) |
| 기술 | C# WPF, .NET 10 LTS, win-x64, 런타임은 PC 에 따로 설치(.NET 10 Desktop Runtime, v0.2.3 부터) |
| 외부 패키지 | 없음(NuGet 패키지 0개) |
| 바깥 도구 | `git.exe`, `powershell.exe`, 휴대용 `gcc`, `cl2000` 을 프로세스로 부른다 |

## 2. 공개 저장소 경계

| 넣는 것 | 넣지 않는 것 |
|---|---|
| 프로그램 소스 | 사이트 이름, 사이트 표, 프로파일·별칭 이름 |
| 문법 표(공개 코어 헤더의 매크로 이름·범위) | 레거시 발췌, 앱 저장소 커밋 해시 |
| 코어 상수 표(입출력 ID, 시퀀스 ID, 파라미터 한계) | 사내 깃 주소, 앱 저장소 주소 기본값 |
| 지어낸 시험 사이트 `tests/fixtures/T900_DEMO` | 회차 이미지, 실제 사이트로 만든 기대값 |

- 앱 저장소 주소는 소스에 기본값을 두지 않는다. 처음 켤 때 받아 설정에 둔다(**내 판단**). 코어 주소는 공개라 기본값을 둔다.
- 실제 사이트로 하는 수용 시험(사양 11절 A-1\~A-4 등)은 환경 변수 `DCU_APP_ROOT`(앱 저장소를 받은 폴더)가 있을 때만 돈다. 없으면 건너뛴다. 사이트별 기대값(조각 수, 경고 기준선)은 앱 저장소에 둔다(**내 판단**).

## 3. 구성

```
AGV_DCU_TableEditor/
  src/TableEditor.Engine/    클래스 라이브러리(net10.0). 화면·Windows 와 무관
    Text/                    글자 → 조각(읽기·쓰기)
    Grammar/                 문법 표, 코어 상수 표, 파일 구역 표
    Model/                   조각 위의 뜻(프로파일, 태그 규칙, 시퀀스, 수동 사슬), 이름 사전, 편집 명령
    Check/                   검사 규칙
    Ops/                     프로세스 실행, 깃, 태그 압축, 빌드, 회차, 코어 버전 변경, 오류 글 해석
  src/TableEditor.Cli/       tedit.exe
  src/TableEditor.App/       TableEditor.exe(WPF, net10.0-windows)
  tests/TableEditor.Tests/   시험 실행 파일(패키지 없이 assert)
  tests/fixtures/T900_DEMO/  지어낸 사이트. 문법 표의 모든 매크로가 한 줄 이상
  docs/
```

| 부분 | 의존 | 까닭 |
|---|---|---|
| Engine | 없음 | 웹으로 갈 때 그대로 쓴다(사양 10.3절). 깃·빌드도 화면 일이 아니라 여기에 둔다 |
| Cli | Engine | 화면 없이 왕복·검사·빌드를 돌린다. 수용 시험과 손 편집 표 검사에 쓴다 |
| App | Engine | 화면은 Engine 의 모델·명령·결과만 묶는다. 표 글자를 직접 만지지 않는다 |
| Tests | Engine | 패키지를 안 쓰므로 실행 파일 하나. 종료 코드 0 = 통과 |

프로젝트를 더 쪼개지 않는다(**내 판단**). 깃·빌드를 따로 떼야 할 까닭이 생기면 그때 나눈다.

## 4. 엔진

### 4.1 한 가지 원본: 조각 목록

```
바이트 → [Text] 조각 목록 → [Model] 뜻 보기 → [Check] 결과
              ↑                    │
              └── 편집 명령 ───────┘      조각 목록 → 바이트
```

- 파일 하나 = 조각 목록(문장 / 주석 / 빈 줄 / 원문, 사양 5.1절). 조각마다 원문 글자 구간을 든다.
- 모델은 조각의 사본이 아니다. 조각을 가리키는 보기다. 편집 명령이 조각을 바꾸면 그 문장만 다시 풀어 보기를 고친다.
- 그래서 원본이 하나뿐이다. "읽고 그대로 쓰면 바이트 동일"(사양 5.5절)이 구조에서 나온다. 안 고친 조각은 원문 구간을 그대로 내보낸다.
- 문장 = 들여쓰기 + 매크로 이름 + 인자 목록 + 꼬리 주석. 인자 = 앞 공백 + 글자 + 뒤 공백 + 풀이 나무(이름 / 숫자 / 안쪽 묶음 / 모름). 인자 하나를 고치면 그 인자의 글자만 바뀐다(사양 5.4절).
- 읽을 수 없는 파일(UTF-8 아님, BOM 있음, 구역 표지 짝 안 맞음)은 통째 원문·읽기 전용으로 연다(**내 판단**: 앞 두 경우. 뒤는 사양 R-2).

### 4.2 문법 표가 네 곳을 움직인다

문법 표 한 줄 = 매크로 하나(두 뜻 이름은 자리별로 한 줄씩).

| 칸 | 내용 | 쓰는 곳 |
|---|---|---|
| 이름, 자리 | 매크로 이름과 쓸 수 있는 구역(프로파일 표, 태그 규칙, 태그 동작, 시퀀스 스텝, ACT, 수동, 입력 조건, 확장 조건) | 읽기 |
| 인자 칸 | 칸마다 종류(이름 사전 종류 / 고정 낱말 / 숫자 범위·단위 / 조건 / 라벨), 생략·여러 개 | 읽기, 검사, 화면 |
| 꼴 | 괄호 안 공백 있음·없음(사양 4.0·5.4절) | 쓰기 |
| 태그 칸 수, ACT 금지 | 동작 칸 합, 금지 스텝 | 검사, 화면(흐리게) |
| 머리 이름, 분류 | 한글 낱말, 팔레트 분류·색 | 화면 |
| 코어 버전 | 그 줄·그 범위가 맞는 코어 버전 범위 | 검사(V-1, 범위) |

- 읽기·쓰기·검사 범위·화면 블록이 모두 이 표에서 나온다. 매크로가 늘면 표에 한 줄을 더한다. 화면 코드는 그대로다.
- 표는 C# 데이터 한 파일이다(**내 판단**). 따로 읽는 형식(JSON 등)을 두지 않는다. 문법이 바뀌면 프로그램을 새로 낸다.
- 파일 구역 표(사양 5.2절: 파일 이름 → 구역 → 그 안에서 되는 문장)와 코어 상수 표(사양 3.9절)도 같은 폴더의 데이터다.
- 표가 코어 헤더와 맞는지는 `tedit headers` 가 본다(사양 V-2, A-13).

### 4.3 이름 사전

- 코어 상수 표 + 사이트 파일(`site.h`, `io_map.h`, `custom_io.h`, `seq_custom.h`, `act_ids.h`, 표 파일 안 `#define`·`LOAD_IF`·`SEQ_BEGIN`·`SEQ_LABELS`)에서 만든다. 종류는 사양 3.1절.
- 사이트 파일의 조각이 바뀌면 사전을 다시 만든다. 사전은 조각에서 계산한 값이지 따로 저장하는 것이 아니다.

### 4.4 편집 명령·되돌리기

| 명령 | 내용 |
|---|---|
| 인자 바꾸기, 꼬리 주석 바꾸기 | 문장 한 개 |
| 문장 넣기·지우기·옮기기 | 구역 안 줄 단위 |
| 원문 글자 바꾸기 | 고급 모드 |
| 묶음 명령 | 여러 파일을 한 번에(프로파일 추가·이름 바꾸기 등, 사양 5.4절 표). 하나라도 막히면 전부 안 한다 |

- 조각 목록은 바꾸지 않는 값이다. 명령은 새 목록을 만든다. 되돌리기·다시 하기는 앞뒤 목록을 바꿔 끼우는 것이다(**내 판단**). 표가 작아서(문장 천 개쯤) 충분하다.
- 디스크 기록(읽은 때의 크기·시각·해시)은 되돌리기 단계와 따로 한 벌이다. 저장하면 모든 단계가 새 기록을 본다. 그래서 저장한 뒤 되돌려 저장하면 되돌린 표가 쓰인다.
- 초안 자동 보관(사양 6절)은 지금 조각 목록을 `build/table_editor/draft/` 에 파일로 쓰는 것이다.

### 4.5 검사

- 규칙 하나 = 함수 하나(번호, 등급, 사이트 모델 → 결과 목록). 번호는 사양 6절 그대로.
- 결과 = 규칙 번호, 등급, 파일, 조각, 칸, 글, 후보 이름.
- 편집할 때마다 사이트 전체를 다시 검사한다. 부분 검사를 두지 않는다(**내 판단**). 느려지면 그때 줄인다.
- 원문 블록이 있는 구역은 순서 검사를 건너뛰고 R-1 을 낸다.

### 4.6 바깥 일(Ops)

| 부분 | 내용 | 지키는 것 |
|---|---|---|
| 프로세스 실행 | 줄 단위 출력, 시간 제한, 취소, 기록 | 화면을 막지 않는다 |
| 깃 | 사양 8.2절의 동작마다 함수 하나. 인자는 함수 안에서만 만든다 | 자유 인자를 받는 길이 없다. 그래서 `--force` 를 만들 수 없다(사양 8.5절). push 전에 주소를 모두 본다. 쓰기 함수는 저장소 맨 위·`master`·코어 저장소 아님일 때만 돈다(아니면 `Refused`). 받아서 표가 바뀌면 올리기는 push 하지 않고 돌려준다(다시 압축한 뒤 다시 올린다) |
| 태그 압축 | 사양 7.2절 3-1\~3-4. 사이트 폴더에 있는 생성물만 다시 만든다 | `warning:` 이 있으면 실패(gcc 는 `LC_ALL=C`. `AGV_DEV_TESTS` 다시 정의 한 가지만 봐준다) |
| 빌드 | `check.ps1 -BuildOnly [-Field]` | 프로그램이 컴파일러를 직접 부르지 않는다. 앱 저장소 스크립트가 원본이다 |
| 회차, 코어 버전 변경 | 사양 7.5절, 8.6절 | 팝업 확인 뒤에만. 회차는 빌드 전에 `.gitignore`·작성자를 보고, 복사 뒤에 실패하면 `release/<사이트>` 를 전 상태로 되돌린다 |
| 오류 글 해석 | 사양 7.3절의 꼴을 정규식 표로. (파일, 줄) → 조각 | 쓸 때 만든 줄 표로 찾는다. `-Field` 사본 경로는 파일 이름으로 되돌린다 |
| 도구 확인 | 사양 7.1절 | 없으면 설정에 표시. 죽지 않는다 |

### 4.7 저장 차례

| 차례 | 동작 | 실패하면 |
|---|---|---|
| 1 | 검사. 오류 0 | 저장 막음. 초안은 남는다 |
| 2 | 디스크 파일이 읽은 뒤 바뀌었는지(읽은 파일 모두. 낡은 초안을 얹은 파일 포함) | 팝업(사양 5.7절) |
| 3 | 바뀐 파일을 모두 임시 파일로 쓴다(사이트 폴더 밖 `build/table_editor/tmp`, 같은 볼륨) → 한꺼번에 바꿔치기 | 원래 파일 그대로 |
| 4 | 다시 읽어 견줌(R-3): 쓴 바이트가 같고, 다시 읽은 표의 검사 오류가 저장 전처럼 0 | 원래 파일 복구 |
| 5 | 압축 태그 표 | 오류 목록에. 커밋 안 함 |
| 6 | `git add -- site/<사이트>` → 커밋 | |

## 5. 명령줄 `tedit`

| 명령 | 내용 | 수용 시험 |
|---|---|---|
| `tedit roundtrip <사이트 폴더>` | 읽고 그대로 써서 해시 견줌 | A-1, A-12 |
| `tedit stat <사이트 폴더>` | 조각 수 | A-2 |
| `tedit check <사이트 폴더> [--core <폴더>]` | 오류·경고 목록. 종료 코드 0 = 오류 없음, 1 = 오류 | A-3, A-4 |
| `tedit headers <core 폴더>` | 문법 표와 코어 헤더 이름 대조 | A-13 |
| `tedit pack <앱 루트> <사이트>` | 압축 태그 표 | A-5 |
| `tedit build <앱 루트> <사이트> [--field]` | 검사 → 압축 → 빌드 | A-7 |
| `tedit round <앱 루트> <사이트> --app-url <주소>` | 회차 내기(압축 → 개발·현장 빌드 → `release/` → 커밋) | 7.5절 |
| `tedit core-update <앱 루트> <사이트> <vX.Y.Z> --app-url <주소> [--from <주소>]`, `tedit core-versions <앱 루트>` | 코어 버전 변경·버전 목록 | A-14 |
| `tedit git-log-check <git.log>` | `--force`·코어 주소 push·자리 밖 `core`·`clean`·`reset --hard` 0건 | A-11 |

- 화면과 같은 엔진 함수를 부른다. 화면에서 되는 빌드는 명령줄에서도 같은 결과다.

## 6. 화면

- 화면 내용은 사양 9절. 여기서는 만드는 방식만 정한다.
- MVVM 을 손으로 짠다(알림 바탕 클래스 + 명령 클래스). 패키지를 쓰지 않는다.
- 블록 하나를 그리는 컨트롤은 하나다. 문법 표의 인자 칸 종류를 보고 칸 편집기(이름 드롭다운 / 낱말 드롭다운 / 숫자 / 조건 / 라벨)를 고른다. 매크로마다 화면을 따로 만들지 않는다.
- 표 화면(프로파일, 태그, 대응표, 수동)은 줄 목록 + 블록 컨트롤이다. 시퀀스도 같은 컨트롤의 세로 목록이다.
- 설정은 `%LOCALAPPDATA%\AGV_DCU_TableEditor\settings.json`(**내 판단**). 저장소 폴더, 앱 주소, 코어 주소, 도구 경로, 이름, 고급 모드.
- 같은 저장소 폴더를 두 창이 열지 못하게 한다(이름 붙인 뮤텍스, **내 판단**). 초안과 커밋이 엉키지 않게.
- 기록 파일은 사양대로 앱 저장소의 `build/table_editor/`(깃 제외)에 둔다.

## 7. 배포

| 항목 | 정한 것 |
|---|---|
| 꼴 | 폴더 하나를 zip 으로. `TableEditor.exe`, `tedit.exe`, `gcc/`(휴대용), `VERSION` |
| 설치 | 없음. 풀어서 실행 |
| 만드는 곳 | 이 저장소의 GitHub Actions(Windows). 태그 `vX.Y.Z` → 시험 → 런타임 포함 게시 → Release 에 zip(**내 판단**) |
| 휴대용 gcc | 배포판·버전을 고정하고 해시를 확인해 zip 에 넣는다. 깃에는 넣지 않는다(9절 확인 요청 6) |
| 개발 PC | `dotnet build` 만으로 된다(패키지 0개라 받을 것이 없다). 런타임 포함 게시는 CI 가 한다 |
| 자동 업데이트 | 1차에 넣지 않는다(사양 10.2절). 넣을 때는 Release 의 목록 파일을 읽는 방식 |

## 8. 단계

사양 10.1절 그대로. 단계마다 이 저장소에서 나오는 것만 적는다.

- 추린 gcc 는 흔한 C/POSIX 헤더(`unistd.h`·`io.h`·`fcntl.h`·`getopt.h`·`strings.h`·`process.h`·`dirent.h`, `sys/` 폴더 통째)도 둔다(74.2 → 74.3 MB). `windows.h` 계열은 뺀다.
- 팝업 지연: 팝업이 뜰 때 큰 영역에 `IsEnabled=false` 를 걸면 UI 자동화(UIA) 이벤트가 트리 전체로 퍼진다. 이것을 없애고 입력 쪽에서 막는다: 마우스는 오버레이가, 키·글자·포커스는 `MainWindow` 가 팝업 밖 대상이면 취소한다. 팝업 열기 약 0.6\~0.9 초 → 0.05 초(이 PC·가장 큰 사이트 측정). 열 때 포커스를 스택에 저장하고(연달아 뜨는 팝업은 원래 자리를 이어받는다) 닫으면 돌려준다. 팝업이 편집을 냈으면 저장한 요소 대신 선택 줄로. 팝업 중에는 탭 전환·검사 줄 이동·열기 같은 명령 없는 길도 막는다.
- 편집 지연: `MainVm.Refresh(defer)` 는 편집·되돌리기 때 보이는 탭만 다시 그리고 나머지는 stale 로 둔다. 탭이 보일 때(`Tab` setter 의 `Flush`)·`GoSeq` 에서 만든다. 마지막 편집이 쓴 줄(`touched`)을 기억했다가 Flush 때 넘긴다. 칸 고치기 약 1.4 초 → 0.5 초(이 PC·가장 큰 사이트 측정).
- 낡은 화면 편집: `EditResult.Base` = 결과를 만든 기준 사이트. `MainVm.Apply`·`EditHistory.Push` 가 기준이 지금 사이트가 아니면 쌓지 않고 알림 "화면 다시 읽음" + 전체 다시 그리기. 명령을 잇는 곳은 맨 처음 사이트가 기준.
- 칸 확정: 칸을 고치는 중에 저장·빌드·회차·받기·팝업 명령을 부르면 `MainVm.CommitPending()` 이 포커스를 풀어 칸을 먼저 확정한다(실패하면 그 명령을 안 한다). 줄을 가진 채 팝업을 여는 명령은 `CommitKeep` 으로 확정 뒤 새 사이트의 같은 줄을 다시 잡는다. 저장은 팝업 뒤 사이트가 바뀌었으면 옛 사이트로 쓰지 않고 중단한다("화면 다시 읽음 · 저장 안 함").
- 릴리스 zip 이름은 `TableEditor-vX.Y.Z-net10-x64.zip`: 옛 클라이언트의 API 폴백이 찾는 `-win-x64.zip` 규칙과 겹치지 않는다. 새 클라이언트의 API 폴백은 버전만 알리고 받지 않는다(runtime 을 모른다). `release.ps1` 은 notes 의 마크다운 이스케이프 `\~` 를 `~` 로 바꿔 쓴다.
- 업데이트 확인 파일: `TableEditor.net10.json`(전체 정보 + `runtime` = 필요한 .NET 메이저)은 v0.2.3 이상이 읽고, `TableEditor.json` 은 v0.2.2 이하가 읽는다. 뒤의 것은 `version`·`published`·`page`·`notes`(첫 줄 = .NET 10 Desktop Runtime 설치 안내)만 둔다. `file`·`sha256` 이 없어 v0.2.2 의 `ParseManifest` 는 받기 불가 릴리스로 읽고(`CanDownload=false`), 알림 토스트 "새 버전"만 낸다. 런타임 없는 PC 에 런타임이 필요한 버전이 깔려 켜지지 않는 일을 막는다. 새 클라이언트는 `runtime` 이 지금 프로세스 메이저보다 크고 dotnet 설치 폴더(`shared\Microsoft.WindowsDesktop.App\<메이저>.*`)에 없으면 받기·교체 없이 "런타임 필요 · .NET N Desktop" 알림.
- v0.2.2 이하 사용자: 자동 교체가 안 된다. .NET 10 Desktop Runtime 을 먼저 설치하고 v0.2.3 zip 을 손으로 한 번 받아 바꿔 넣는다.
